# 初赛 7 分钟演示脚本

## 0. 演示前准备

1. 启动系统：`start_windows.bat`
2. 预热后台数据：`conda run -p "D:/Human/env" python -m app.cli seed-demo-logs --reset`
3. 确认统一评测：`conda run -p "D:/Human/env" python -m app.cli eval-unified --report reports/unified_eval_report.json --markdown-report reports/unified_eval_report.md --strict --fail-under 90`
4. 后台切换数字人为高质量模式，确认音色与视频正常

## 1. 叙事结构

- 0:00-0:40 痛点：景区导览内容固定、游客互动弱、后台缺少可量化洞察
- 0:40-1:20 总览：游客前台 + 管理后台 + planner-first RAG+SQL
- 1:20-2:10 事实问答：展示结构化景区事实回答
- 2:10-3:00 行为分析：展示 semantic SQL 统计能力
- 3:00-3:50 路线推荐：展示 route planner 的节点、时长和讲解重点
- 3:50-4:40 语音与数字人：展示 Whisper、TTS 和数字人联动
- 4:40-5:20 弱 GPS：展示多轮澄清
- 5:20-6:20 管理后台：展示互动数据、失败样例、知识库状态和统一评测
- 6:20-7:00 总结：强调 `99.38/100`、结构化观测和真实场景可用性

## 2. 推荐演示问题

- `灵山梵宫为什么被称为佛教艺术的卢浮宫？`
- `平均停留时间最长的景点是哪些？`
- `我喜欢自然风光和拍照打卡，请推荐一条适合拍照的路线。`
- `我现在定位不准，只看到一座桥和很长的步道，下一站怎么走？`
- `请告诉我明天实时排队多久。`

## 3. 演示重点

- 不是所有问题都统一走 RAG，而是由 planner 先规划。
- 景区事实、游客行为分析、深资料问答和路线推荐各自有明确执行链路。
- 返回结果包含 `plan / evidence / refusal / warnings / observability`。
- 后台和日志能够直接回看这些结构化信息。
- 统一评测最新总分 `99.38/100`，剩余问题只在少量长尾样例。
