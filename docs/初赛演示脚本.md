# 初赛 7 分钟演示脚本

## 0. 演示前准备

1. 启动系统：`start_windows.bat`
2. 预热后台数据：`conda run -p "D:/Human/env" python -m app.cli seed-demo-logs --reset`
3. 生成 1200 题统一评测集：`conda run -p "D:/Human/env" python -m app.cli generate-unified-eval --target 1200 --output tests/unified_eval_cases.jsonl`
4. 跑严格统一评测：`conda run -p "D:/Human/env" python -m app.cli eval-unified --report reports/unified_eval_report.json --markdown-report reports/unified_eval_report.md --strict --fail-under 90`
5. 后台切换数字人模式为“高质量”，试听音色，确认前台能正常生成视频。

## 1. 叙事结构

- 0:00-0:40 痛点：旺季导游不足、传统导览不能互动、管理方缺少游客反馈。
- 0:40-1:20 产品总览：游客端数字人导览 + 管理后台运营驾驶舱。
- 1:20-2:30 智能问答：询问“灵山梵宫为什么被称为佛教艺术的卢浮宫”，展示 DOCX 知识库来源标签。
- 2:30-3:40 个性化路线：点击“历史文化”或“亲子家庭”演示路线卡，展示节点、时长、讲解重点和游客行为依据。
- 3:40-4:40 多模态交互：用语音提问一次，展示“听懂意图 -> 检索资料 -> 生成讲解 -> 数字人出镜”状态链路。
- 4:40-5:30 弱 GPS 加分场景：开启弱 GPS，询问“我只看到桥和长步道，下一站怎么走”，展示多轮澄清。
- 5:30-6:30 管理后台：展示统一评测 99+、知识库状态、游客行为数据、运营建议和失败样例。
- 6:30-7:00 总结亮点：本地知识库准确率、数据源隔离、路线融合推荐、数字人闭环、后台运营价值。

## 2. 推荐演示问题

- `灵山梵宫为什么被称为佛教艺术的卢浮宫？`
- `我是历史文化爱好者，请给我一条灵山胜境深度讲解路线，并说明每个节点讲什么。`
- `我们带孩子来玩，请推荐一条亲子友好的路线，要有互动点和讲解重点。`
- `我喜欢自然风光和拍照打卡，请推荐一条适合拍照的路线，并说明为什么适合多数游客。`
- `平均停留时间最长的景点是哪几个？`
- `请告诉我明天实时排队多久。`
- `我现在定位不准，只看到一座桥和很长的步道，下一站怎么走？`

## 3. PPT 结构

- 需求场景：对应赛题痛点和评分项。
- 整体方案：多模态交互层、RAG 知识层、游客行为分析层、运营后台层。
- 核心技术：FACT/ANALYTICS/RECOMMEND 路由、DOCX/Excel 数据源隔离、弱 GPS 多轮问路、统一评测。
- 产品展示：游客端、路线卡、数字人舞台、管理后台。
- 测试数据：统一评测总分、各数据源准确率、失败样例闭环。
- 创新价值：从“会回答”升级为“可导览、可运营、可验证”。
