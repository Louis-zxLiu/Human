# 演示视频脚本与分镜

建议时长：7 分钟以内  
建议格式：`mp4`  
建议分辨率：1920x1080

## 1. 演示前准备

### 1.1 启动环境

```bat
start_windows.bat
conda run -p "D:/Human/env" python -m app.cli seed-demo-logs --reset
```

### 1.2 确认评测结果

```bat
conda run -p "D:/Human/env" python -m app.cli eval-unified --report reports/unified_eval_report.json --markdown-report reports/unified_eval_report.md --strict --fail-under 90
```

演示时建议展示的关键数字：

- 总题数：`1200`
- 总分：`99.38/100`
- 总失败数：`11`

## 2. 时间轴

| 时间 | 画面 | 解说重点 |
| --- | --- | --- |
| 0:00-0:30 | 封面或系统首页 | 项目面向真实景区服务，不只是聊天演示 |
| 0:30-1:00 | 产品总览 | 游客前台 + 管理后台 + planner-first RAG+SQL |
| 1:00-1:50 | 事实问答 | 结构化景区事实优先，回答有依据 |
| 1:50-2:40 | 行为分析 | semantic SQL 负责统计，不靠模型编数字 |
| 2:40-3:30 | 路线推荐 | route planner 输出节点、时长、讲解重点 |
| 3:30-4:20 | 语音与数字人 | Whisper、TTS、数字人视频形成闭环 |
| 4:20-5:00 | 弱 GPS | 多轮澄清而不是伪造定位 |
| 5:00-5:50 | 管理后台 | 互动数据、失败样例、知识库状态、评测结果 |
| 5:50-6:30 | 响应契约与日志 | `plan / evidence / refusal / observability` |
| 6:30-7:00 | 总结 | 可服务、可运营、可评测、可回放 |

## 3. 分镜脚本

### 镜头 1：开场

旁白：

```text
我们的作品是灵山胜境导览服务 AI 数字人系统。它面向真实景区服务场景，既服务游客，也服务景区运营。
```

### 镜头 2：系统总览

画面：

- 游客前台
- 管理后台
- 前后端整体布局

旁白：

```text
系统由游客前台、管理后台、planner-first RAG+SQL 引擎和数字人链路共同组成，不是单点问答功能，而是完整工程。
```

### 镜头 3：景区事实问答

示例问题：

```text
灵山梵宫为什么被称为佛教艺术的卢浮宫？
```

旁白：

```text
这类问题优先走结构化景区事实链路，必要时补充检索证据。系统会把来源依据和执行计划保留下来，避免自由发挥。
```

### 镜头 4：行为分析

示例问题：

```text
平均停留时间最长的景点是哪些？
```

旁白：

```text
统计类问题优先进入 semantic SQL 链路，分析结果直接来自行为库，而不是模型自己生成数字。
```

### 镜头 5：路线推荐

示例问题：

```text
我喜欢自然风光和拍照打卡，请推荐一条适合拍照的路线。
```

旁白：

```text
route planner 会综合景区知识、行为偏好和讲解重点，输出节点顺序、时长安排和推荐依据。
```

### 镜头 6：语音与数字人

旁白：

```text
前台支持语音提问。Whisper 负责识别，planner-first pipeline 负责回答，Edge-TTS 负责播报，SoulX-FlashHead 负责数字人视频生成。
```

### 镜头 7：弱 GPS

示例问题：

```text
我现在定位不准，只看到一座桥和很长的步道，下一站怎么走？
```

旁白：

```text
系统不会伪造精确定位，而是通过地标描述和多轮澄清帮助游客继续导览。
```

### 镜头 8：管理后台

旁白：

```text
后台可以看到互动量、意图分布、满意度趋势、热点问题、失败样例和知识库状态，也可以直接查看评测结果。
```

### 镜头 9：响应契约与日志

建议展示：

- `plan`
- `evidence`
- `refusal`
- `warnings`
- `observability`

旁白：

```text
本次升级后，我们把回答结果统一为结构化响应契约，并同步写入日志，方便前端展示、失败回放和后续线上观测。
```

### 镜头 10：评测结果

旁白：

```text
我们构建了 1200 题统一评测集，最新严格总分 99.38。剩余长尾问题只集中在少量深资料术语覆盖和个别 SQL top5 尾序表达。
```

### 镜头 11：结尾

旁白：

```text
这套系统已经具备真实场景可用的工程特征：能服务游客，能支撑运营，能结构化观测，也能被统一评测验证。
```

## 4. 录制注意事项

- 不展示 `.env`、密钥或个人账号信息。
- 不演示系统未承诺的实时外部数据能力。
- 优先录制 20 到 40 秒可完成回答的问题，避免数字人生成等待过长。
- 录制前运行 `seed-demo-logs --reset`，确保后台图表有数据。
