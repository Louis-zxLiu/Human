# 演示视频脚本与分镜

视频要求：`.avi`、`.mp4` 或 `.wmv`，时长不超过 7 分钟。
建议格式：`mp4`。
建议分辨率：1920x1080。
建议录制方式：全屏录制浏览器 + 必要时插入 PPT 片头。

## 1. 演示前准备

AutoDL 4090 决赛环境：

```bash
bash scripts/autodl_prepare.sh
bash scripts/autodl_start.sh
bash scripts/finals_preflight.sh
```

主访问入口使用 AutoDL「自定义服务」中 `6006` 对应公网地址；备用入口使用本地 SSH 隧道：

```powershell
ssh -CNg -L 6006:127.0.0.1:6006 root@<AutoDL主机> -p <SSH端口>
```

本地 Windows 录屏或兜底环境：

```bat
start_windows.bat
conda run -p "D:/Human/env" python -m app.cli seed-demo-logs --reset
conda run -p "D:/Human/env" python -m app.cli generate-unified-eval --target 1200 --output tests/unified_eval_cases.jsonl
conda run -p "D:/Human/env" python -m app.cli eval-unified --report reports/unified_eval_report.json --markdown-report reports/unified_eval_report.md --strict --fail-under 90
```

检查项：

- 游客前台可访问：`http://127.0.0.1:8000/`
- 管理后台可访问：`http://127.0.0.1:8000/admin`
- 管理员账号可登录：`admin / admin123`
- 后台数字人模式切换为“高质量”
- 游客端演示模式优先使用“实时流式”，如现场网络抖动则切换“稳定 MP4”
- 音色试听正常
- 前台能生成数字人视频

## 3. 分镜脚本

### 镜头 1：开场

画面：

- PPT 封面或登录页。

旁白：

```text
大家好，我们的作品是灵山胜境导览服务 AI 数字人系统。系统面向智慧景区导览场景，提供游客端数字人讲解和管理端运营分析能力。
```

### 镜头 2：游客端总览

画面：

- 进入游客前台。
- 展示左侧历史会话、中间对话区、右侧数字人舞台。

旁白：

```text
游客端采用视频主位布局，中间是实时对话区，右侧是数字人舞台。系统支持文本提问、语音提问、路线推荐和弱 GPS 模式。
```

### 镜头 3：景区事实问答

操作：

输入：

```text
灵山梵宫为什么被称为佛教艺术的卢浮宫？
```

展示：

- DOCX 景区知识库标签。
- 回答内容。
- 数字人视频。

旁白：

```text
系统会先判断这是景区事实问题，然后从本地 DOCX 知识库中检索证据。回答会标注数据源，避免把游客行为统计误当景区事实。
```

### 镜头 4：路线推荐

操作：

- 点击“历史文化”演示路线。

展示：

- 路线节点。
- 预计游览时长。
- 讲解重点。
- 游客行为依据。

旁白：

```text
路线推荐不是简单罗列景点，而是融合游客兴趣、景区知识和行为数据，给出路线节点、讲解重点和适合原因。
```

### 镜头 5：语音和数字人

操作：

- 按住语音按钮提问：

```text
带孩子来玩，有哪些适合亲子的互动点？
```

展示：

- 语音识别文本。
- 生成进度。
- 数字人视频播放。

旁白：

```text
多模态链路由 Whisper 负责语音识别，Edge-TTS 负责语音合成，SoulX-FlashHead 负责数字人视频生成。前台会展示听懂、检索、生成和出镜四个阶段，降低等待感。
```

### 镜头 6：弱 GPS 场景

操作：

- 开启弱 GPS。
- 输入：

```text
我现在定位不准，只看到一座桥和很长的步道，下一站怎么走？
```

展示：

- 候选位置。
- 多轮澄清。
- 后续路线建议。

旁白：

```text
景区内常出现 GPS 信号弱或定位漂移。系统不会编造精确位置，而是根据游客描述的桥、步道、广场等地标进行多轮澄清。
```

### 镜头 7：管理后台

画面：

- 进入后台。
- 展示 KPI、图表、运营建议、知识库状态。

旁白：

```text
管理后台面向景区运营人员，展示互动量、意图分布、推荐标签、满意度趋势和游客关注点。系统还会把拒答样例和热点问题转化为运营建议，帮助景区维护知识库。
```

### 镜头 8：统一评测

画面：

- 后台统一评测卡片或评测报告。

旁白：

```text
我们构建了可复现生成的统一自测集，共 1200 题，覆盖 DOCX 事实、RAG 深度资料、游客行为 SQL、路线推荐融合和边界拒答。当前严格评测总分 94.33，已经通过 90 分提交线，报告中的待优化样例会继续反哺知识库和路由策略。
```

### 镜头 9：总结

画面：

- 回到 PPT 总结页或后台首页。

旁白：

```text
本系统围绕游客体验和景区管理形成完整闭环：游客可以自然互动，数字人可以出镜讲解，后台可以沉淀运营数据，评测体系可以验证问答准确率。以上就是我们的作品展示。
```

## 4. 录制注意事项

- 不展示 `.env`、API Key、个人账号等敏感信息。
- 不演示实时票价、实时排队、实时停车位等系统未承诺能力。
- 数字人回答建议选择 20-40 秒口播问题，避免视频生成等待过长。
- 后台录制前运行 `seed-demo-logs --reset`，保证图表不空。
- 若出现 Chroma telemetry 警告，不录入视频画面；该警告不影响系统功能。
