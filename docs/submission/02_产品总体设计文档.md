## 1. 项目背景

智慧景区建设正在从“信息展示”走向“实时互动”和“数据驱动运营”。传统导览服务存在以下问题：

- 旺季导游资源不足，游客等待成本高。
- 录音导览内容固定，无法回答个性化问题。
- 游客与设备缺少情感连接，体验不够自然。
- 景区管理方难以量化游客关注点、满意度和服务短板。

本项目构建“景区导览服务 AI 数字人系统”，面向游客提供实时问答、路线推荐、语音交互和数字人讲解，面向管理方提供知识库状态、游客行为分析、满意度趋势和运营建议。

## 2. 设计目标

系统目标与赛题要求对应如下：

| 赛题要求 | 系统设计 |
| --- | --- |
| 多模态交互 | 支持文本输入、语音输入、语音合成、数字人视频反馈 |
| 智能问答与讲解 | 基于 DOCX 本地知识库回答景区历史、文化、特色问题 |
| 个性化推荐 | 根据游客兴趣生成历史文化、亲子家庭、自然风光等路线 |
| 管理后台 | 展示互动数据、知识库状态、游客行为洞察和运营建议 |
| 数字人形象管理 | 支持头像上传、音色试听、画质模式切换 |
| 事实准确率 | 建立统一评测集，当前总分 `99.75/100` |

## 3. 总体架构

系统采用四层架构：

```text
游客/管理员
   |
   v
多模态交互层：React 前端、文本输入、语音输入、数字人视频舞台
   |
   v
智能服务层：FastAPI、ASR、TTS、数字人生成、会话日志
   |
   v
RAG 与数据分析层：FACT / ANALYTICS / RECOMMEND 路由、DOCX 知识库、Excel 行为分析
   |
   v
运营后台层：数据驾驶舱、评测健康度、知识库状态、运营建议
```

### 3.1 多模态交互层

前端使用 React + Vite 实现，包含：

- 登录页
- 游客前台
- 管理后台

游客前台支持：

- 文本问答
- 语音提问
- 推荐路线卡片
- 数据源标签
- 生成进度展示
- 数字人视频主位
- 本地历史会话

### 3.2 智能服务层

后端使用 FastAPI 实现，负责：

- 用户认证
- 文本交互接口
- 音频交互接口
- 管理后台接口
- 日志记录
- 数字人运行配置

语音与数字人链路：

1. 浏览器录制音频并上传。
2. Whisper 完成 ASR。
3. RAG Pipeline 生成回答。
4. Edge-TTS 生成语音。
5. SoulX-FlashHead 生成口型同步视频。
6. 前台播放数字人视频。

### 3.3 RAG 与数据分析层

系统使用三类业务路由：

| 路由 | 数据源 | 用途 |
| --- | --- | --- |
| `FACT` | DOCX 景区知识库 | 景点事实、历史文化、位置、开放信息 |
| `ANALYTICS` | Excel 入库后的 SQLite 行为数据 | 访问量、停留时长、消费、满意度等统计 |
| `RECOMMEND` | DOCX 知识 + 行为数据 | 个性化路线推荐和讲解重点 |

核心原则：

- 景区事实只来自 DOCX 知识库。
- 游客行为数据只用于统计和推荐依据。
- 无证据问题统一拒答，避免编造。

### 3.4 运营后台层

后台以“景区运营驾驶舱”为设计目标，展示：

- 互动量
- 意图分布
- 推荐标签分布
- 满意度趋势
- 游客关注焦点
- 热门分析问题
- 失败样例
- 知识库健康度
- 统一评测得分
- 运营建议
- 数字人配置

## 4. 数据设计

### 4.1 景区知识数据

来源：

- `data/knowledge_base/灵山胜境 景点结构化数据集.docx`
- `data/knowledge_base/灵山胜境：历史、文化、景点特色与个性化游览指南.docx`

用途：

- 景点结构化字段提取。
- 历史文化资料检索。
- 路线讲解重点生成。
- 事实问答评测。

### 4.2 游客行为数据

来源：

- `data/raw_sql_data/景点景区旅游数据行为分析数据.xlsx`

入库后用于：

- 访问量统计
- 平均停留时长
- 消费构成
- 满意度趋势
- 年龄和性别差异
- 景点类型偏好

### 4.3 交互日志数据

系统记录：

- 用户问题
- AI 回答
- 意图类型
- 情感倾向
- 关注点
- 匹配景点
- 推荐标签
- 响应耗时
- 失败或拒答类型

这些日志用于后台分析和演示数据预热。

## 5. 核心功能设计

### 5.1 景区知识问答

用户可询问：

- 景点介绍
- 历史背景
- 文化内涵
- 游玩亮点
- 开放信息
- 建筑参数

系统会优先从结构化 DOCX 入库结果中回答，再补充 RAG 检索。

### 5.2 游客行为分析

用户可询问：

- 平均停留时间最长的景点
- 各景点类型访问量排名
- 不同性别游客偏好
- 月度访问趋势
- 消费最高的景点类型

系统通过安全 SQL 查询游客行为库，回答中明确标注“基于游客行为数据分析”。

### 5.3 个性化路线推荐

系统支持以下推荐标签：

- 历史文化
- 风景打卡
- 亲子同游
- 建筑艺术
- 轻松慢游
- 经典首游

每条推荐路线包含：

- 路线标题
- 推荐原因
- 预计游览时长
- 路线节点
- 节点讲解摘要
- 游客行为依据

### 5.4 弱 GPS 多轮问路

系统不承诺真实高精度定位，而是针对景区常见“GPS 信号弱、游客描述地标”的情况进行辅助：

1. 用户开启弱 GPS 模式。
2. 用户描述附近地标。
3. 系统推断候选景点。
4. 信息不足时继续追问。
5. 信息足够时给出当前位置和后续路线建议。

### 5.5 管理后台

后台功能包括：

- 数据驾驶舱
- 知识库状态
- 行为数据状态
- 统一评测状态
- 运营建议
- 数字人头像上传
- 音色试听和保存
- 数字人画质模式切换

## 7. 创新点

### 7.1 数据源隔离

系统明确区分景区事实资料和游客行为数据，避免把行为统计误当景区事实，也避免用景区文档回答行为统计问题。

### 7.2 路线融合推荐

路线推荐同时结合：

- 游客兴趣标签
- 景区 DOCX 知识
- 游客行为数据
- 讲解重点
- 预计游览时长

### 7.3 弱 GPS 多轮问路

针对景区定位不稳定场景，使用地标描述和多轮澄清帮助游客确认位置，是对真实景区复杂场景的补充考虑。

### 7.4 统一自测评估体系

系统构建 220 题统一评测集，覆盖：

- DOCX 结构化事实
- DOCX RAG 深度资料
- 游客行为 SQL
- 推荐融合
- 边界拒答

当前评测总分为 `99.75/100`，失败样例数为 `0`。

## 8. 安全与边界

系统不编造以下信息：

- 实时票价
- 实时排队时间
- 实时停车位
- 未收录的演出安排
- 未提供证据的景区事实

当证据不足时，系统会提示补充条件或拒答，保证景区讲解的可信度。
