# 第二批改造说明

## 目标

第二批改造围绕比赛得分与答辩说服力展开，重点完成四件事：

1. 强化灵山景区事实知识层，减少事实问答漂移。
2. 建立标准题集与回归脚本，让准确率可验证。
3. 将 GPS 弱信号场景升级为多轮定位流程。
4. 把推荐结果、后台统计与失败样例真正展示出来。

## 本批核心改造

### 1. 景区知识补强

- `attractions` 继续作为事实问答单一可信源。
- 对当前缺字段最明显的 `灵山大佛` 做了定向补录。
- 事实回答优先走结构化字段，RAG 只做补充，不做唯一来源。

### 2. 统一评测闭环

- 新增 `tests/manual_eval_questions.json`
- 新增 `tests/run_eval.py`
- 目前题集按 `FACT / ANALYTICS / RECOMMEND` 三类组织，可用于回归验证和答辩展示。

### 3. GPS 弱信号多轮定位

- 新增轻量位置模块，维护灵山地标词典。
- 在弱 GPS 场景下，系统不再直接“假装知道位置”，而是先追问地标。
- 根据用户补充描述给出候选位置，并在确定后继续输出路线建议或推荐结果。

### 4. 推荐与后台展示增强

- 推荐结果统一输出：
  - 推荐路线
  - 适合原因
  - 预计游览时长
  - 建议讲解重点
  - 游客行为分析补充
- 后台补充展示：
  - 推荐标签分布
  - 热门分析问题
  - 热门景点偏好
  - 最近失败/拒答样例
  - 数据状态卡片

## 数据分层治理说明

比赛方提供的 `景点景区旅游数据行为分析数据.xlsx` 明确用于游客行为分析，不作为灵山景区事实知识库。

- 景区知识层：只回答灵山景点事实、历史、文化、亮点、位置与开放信息。
- 行为分析层：只回答游客偏好、消费、停留时长、满意度、热门类型等统计问题。
- 推荐层：以景区知识为主，以行为分析为辅。

这样做可以避免把跨景区行为数据误当作灵山景区官方事实，从而提高事实问答准确率与系统可解释性。
